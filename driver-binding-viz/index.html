UEFI Driver Binding Protocol 概述

理解 EDK2 驅動程式如何被動態綁定到設備

🔌

什麼是 Driver Binding Protocol？

EFI_DRIVER_BINDING_PROTOCOL 是 UEFI 驅動程式模型的核心。每個符合 UEFI 驅動程式模型的驅動程式都必須實作此協定，並將其安裝在自己的映像句柄（Image Handle）上。DXE Core 透過 ConnectController() 服務，以此協定為媒介，動態地將驅動程式與設備句柄（Device Handle）綁定。

⚙️

為什麼需要此機制？

UEFI 採用資料驅動的設備探測模型：驅動程式不在載入時就與硬體綁定，而是由系統在需要時透過標準 API 進行匹配。這使得驅動程式的新增或替換不需修改核心，提供高度的可擴充性與可替換性。

三個核心函式

Supported()

測試此驅動程式是否支援指定的 Controller Handle。通常嘗試開啟特定協定（例如 PCI I/O Protocol）並驗證 Vendor ID/Device ID。必須是冪等操作，不得改變系統狀態。

Start()

在指定的 Controller Handle 上啟動此驅動程式。在此函式中：①開啟所需協定（BY_DRIVER）②配置硬體資源③在控制器或子句柄上安裝此驅動程式提供的協定。

Stop()

從指定的 Controller Handle 停止此驅動程式。必須撤銷 Start() 所做的一切：①解除安裝協定②關閉開啟的協定③銷毀子句柄④釋放所有資源。

ConnectController() 的角色

DXE Core 提供的 BS->ConnectController() 是驅動程式綁定的入口。它遍歷所有已安裝的 EFI_DRIVER_BINDING_PROTOCOL，對每個協定依優先順序（Version 欄位）呼叫 Supported()，找到匹配的驅動程式後呼叫 Start()。

內部核心資料結構

EDK2 DXE Core 如何在記憶體中表示句柄與協定

IHANDLE 'hand'
每個 EFI_HANDLE 實際上是一個指向 IHANDLE 結構的指標。IHANDLE 是 EDK2 Core 私有的結構（定義於 DxeMain.h），外部程式碼只能看到 VOID* 類型的 EFI_HANDLE。
Signature Signature：魔法數字 'hand'，用於驗證指標有效性
AllHandles AllHandles：連接到全域句柄資料庫 gHandleList 的 LIST_ENTRY
Protocols Protocols：此句柄上所有已安裝協定的 LIST_ENTRY 鏈結串列頭部
Key Key：單調遞增的唯一識別鍵，供 LocateHandleBuffer 使用
PROTOCOL_INTERFACE 'pi'
每次呼叫 InstallProtocolInterface() 都會建立一個 PROTOCOL_INTERFACE 結構，記錄「在哪個句柄上安裝了哪個協定、介面指標是什麼」。
Signature Signature：'pi'，有效性驗證
Link Link：連接到所屬 IHANDLE.Protocols 串列的 LIST_ENTRY
Handle Handle：回指所屬的 IHANDLE
Protocol Protocol：指向對應 PROTOCOL_ENTRY 的指標（含 GUID）
Interface Interface：指向實際協定結構的 void* 指標
OpenList OpenList：透過 OpenProtocol() 開啟此協定的所有記錄串列
PROTOCOL_ENTRY 'pe'
PROTOCOL_ENTRY 是全域協定資料庫（gProtocolDatabase）中的一個項目，代表某個 GUID 對應的協定類型。同一 GUID 在整個系統中只有一個 PROTOCOL_ENTRY。
Signature Signature：'pe'
AllEntries AllEntries：連接到 gProtocolDatabase 串列
ProtocolID ProtocolID：此協定的 EFI_GUID
Protocols Protocols：所有安裝了此協定的 PROTOCOL_INTERFACE 串列
Notify Notify：此協定的 RegisterProtocolNotify 回呼串列
三層結構關係圖
gHandleList 串聯所有 IHANDLE；每個 IHANDLE.Protocols 串聯其上所有 PROTOCOL_INTERFACE；每個 PROTOCOL_INTERFACE.Protocol 回指全域 PROTOCOL_ENTRY。

實際案例：PCI 設備完整綁定鏈

從 PCI 列舉到 Disk I/O Protocol 的完整 Driver Binding 過程

以下展示一個 NVMe SSD 連接在 PCIe 匯流排上時，完整的 Driver Binding 鏈：PCI Host Bridge Driver → PCI Bus Driver → NVMe Controller Driver。每一層的父驅動程式建立子句柄後，下一層驅動程式再綁定到子句柄。

PCI Host Bridge（Root Handle）

PCI Host Bridge Driver

PCI Host Bridge Driver 在 Root Bridge Handle 上安裝 EFI_PCI_ROOT_BRIDGE_IO_PROTOCOL。此句柄代表整個 PCI 匯流排空間。

EFI_DEVICE_PATH_PROTOCOL EFI_PCI_ROOT_BRIDGE_IO_PROTOCOL
PCI Bus Driver 建立 PCI Device Handles

PCI Bus Driver

PCI Bus Driver 的 Start() 列舉所有 PCI 設備，對每個設備建立子 EFI_HANDLE，安裝 EFI_PCI_IO_PROTOCOL 和 EFI_DEVICE_PATH_PROTOCOL。

EFI_DEVICE_PATH_PROTOCOL EFI_PCI_IO_PROTOCOL → child handles per PCI device
NVMe Driver 綁定到 NVMe PCI Device

NVMe Controller Driver

NVMe Controller Driver 的 Supported() 確認 PCI Class Code 為 0x010802（NVMe），Start() 初始化控制器並安裝 EFI_NVM_EXPRESS_PASS_THRU_PROTOCOL 和 EFI_BLOCK_IO_PROTOCOL。

EFI_PCI_IO_PROTOCOL EFI_NVM_EXPRESS_PASS_THRU_PROTOCOL EFI_BLOCK_IO_PROTOCOL
Partition Driver 建立磁碟分割子句柄

Partition Driver

Partition Driver 透過 EFI_BLOCK_IO_PROTOCOL 讀取 GPT 表，對每個分割區建立子句柄，安裝 EFI_BLOCK_IO_PROTOCOL（分割區範圍）和 EFI_DEVICE_PATH_PROTOCOL（含 GPT 分割區節點）。

EFI_BLOCK_IO_PROTOCOL (parent) EFI_BLOCK_IO_PROTOCOL (partition) → child handles per GPT partition
Handle Database — NVMe Binding Chain
