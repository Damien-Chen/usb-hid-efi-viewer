概述

UEFI Protocol Services 概述

理解 EDK2 中如何存取和查詢 Handle Database 上的 Protocol 介面

🔍

什麼是 Protocol Services？

Protocol Services 是 UEFI Boot Services Table 中一組用來發現和存取 Protocol 介面的 API。它們是驅動程式與硬體、驅動程式與驅動程式之間溝通的核心橋樑。每個 Protocol 以 GUID 識別，安裝在 Handle 上，透過這些服務讀取。

❓

為什麼有 4 個不同的函式？

EFI 1.0 僅有 HandleProtocol；UEFI 2.0 引入了 OpenProtocol 以支援驅動程式模型的排他性開啟與追蹤機制。LocateProtocol 簡化了查找系統全域單例（singleton）協定的流程，而 LocateHandleBuffer 提供了一次取得所有匹配 Handle 的便利方式。四個函式在不同場景各有最佳用途。

Protocol Services API

OpenProtocol

最完整的協定存取函式。支援 6 種開啟屬性（Attributes），可追蹤誰開啟了哪個協定，支援排他性存取和衝突偵測。UEFI 驅動程式模型的標準用法。

HandleProtocol

EFI 1.0 的簡化版。等同於 OpenProtocol 加 BY_HANDLE_PROTOCOL 屬性。無法追蹤開啟者身份，不建議在 UEFI 驅動程式模型中使用。

LocateProtocol

在整個 Handle Database 中找到第一個安裝了指定 GUID 協定的 Handle，直接返回 Interface 指標。最適合查找系統全域的單例協定。

LocateHandleBuffer

找出所有安裝了指定協定的 Handle，配置並回傳一個 EFI_HANDLE 陣列。呼叫者必須 FreePool 回傳的緩衝區。用於列舉所有符合條件的設備。

核心資料結構

理解 DXE Core 如何在記憶體中追蹤協定的開啟記錄

OPEN_PROTOCOL_DATA 'op'
每次 OpenProtocol 呼叫（除 TEST_PROTOCOL 外）都會建立一筆 OPEN_PROTOCOL_DATA 記錄，掛在 PROTOCOL_INTERFACE.OpenList 上。它記錄了「誰（AgentHandle）」以「哪種模式（Attributes）」開啟了這個協定介面，以及「在哪個控制器（ControllerHandle）」的上下文中。
Signature Signature：驗證用魔法數字
Link Link：連接到 PROTOCOL_INTERFACE.OpenList 的 LIST_ENTRY
AgentHandle AgentHandle：開啟此協定的驅動程式映像句柄
ControllerHandle ControllerHandle：被管理的控制器句柄（BY_DRIVER 時使用）
Attributes Attributes：開啟模式（BY_DRIVER, EXCLUSIVE, BY_CHILD_CONTROLLER 等）
OpenCount OpenCount：參考計數
PROTOCOL_INTERFACE 'pi'
PROTOCOL_INTERFACE 代表「某個 Handle 上安裝了某個協定」的記錄。其 OpenList 欄位是所有開啟此協定的消費者追蹤串列的頭部。
OpenList OpenList：所有 OPEN_PROTOCOL_DATA 記錄組成的串列頭部
OpenProtocol 追蹤鏈
IHANDLE.Protocols → PROTOCOL_INTERFACE → OPEN_PROTOCOL_DATA 鏈。DXE Core 透過此鏈確認哪些驅動程式正在使用哪些協定，並在 DisconnectController 時據此決定需要 Stop 哪些驅動程式。

HandleProtocol — 簡化包裝

理解 HandleProtocol 是 OpenProtocol 的 Legacy 封裝

HandleProtocol() 是 EFI 1.0 原始 API。在 UEFI 2.x 中，它的內部實作僅是對 OpenProtocol() 的一層薄包裝，使用 BY_HANDLE_PROTOCOL 屬性。

等效呼叫

HandleProtocol(Handle, Protocol, &Interface) 在 DXE Core 內部等同於：OpenProtocol(Handle, Protocol, &Interface, gDxeCoreImageHandle, NULL, EFI_OPEN_PROTOCOL_BY_HANDLE_PROTOCOL)

// HandleProtocol(Handle, Protocol, &Interface) // is internally equivalent to: OpenProtocol( Handle, Protocol, &Interface, gDxeCoreImageHandle, // AgentHandle NULL, // ControllerHandle EFI_OPEN_PROTOCOL_BY_HANDLE_PROTOCOL );

為什麼不建議在驅動程式中使用？

HandleProtocol 不提供 AgentHandle/ControllerHandle 追蹤資訊。DisconnectController 無法識別協定的使用者，導致系統在嘗試拆除驅動程式綁定時，無法正確通知相關驅動程式執行清理。在 UEFI 驅動程式模型中，應始終使用 OpenProtocol(BY_DRIVER)。

常見使用模式

BIOS 工程師在日常開發中最常用的協定服務模式

Supported() 檢查模式

在 Supported() 中用 OpenProtocol(BY_DRIVER) 嘗試開啟目標協定，檢查設備屬性後立即 CloseProtocol()。必須為冪等操作，不改變任何狀態。

Start() 綁定模式

在 Start() 中用 OpenProtocol(BY_DRIVER) 正式取得排他性存取權，初始化硬體，安裝新協定。BY_DRIVER 確保不會有其他驅動程式同時管理此控制器。

單例查找模式

使用 LocateProtocol() 查找系統全域的單例協定，如 EFI_VARIABLE_ARCH_PROTOCOL、EFI_SMM_COMMUNICATION_PROTOCOL。這些協定在系統中只有一個實例。

設備列舉模式

使用 LocateHandleBuffer(ByProtocol) 取得所有匹配的 Handle，然後對每個 Handle 呼叫 OpenProtocol 取得 Interface。常用於在啟動管理器中列舉所有 Block IO 裝置。

匯流排子句柄模式

匯流排驅動程式在子句柄上使用 OpenProtocol(BY_CHILD_CONTROLLER) 開啟父句柄的協定，建立親子關係追蹤。DisconnectController 據此知道需先停止子句柄。
